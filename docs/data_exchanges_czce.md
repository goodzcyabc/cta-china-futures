# 郑州商品交易所(CZCE)公开数据接入

模块 `src/cta/data/exchanges/czce.py`;落盘布局与统一字段见 `base.py`(`data/exchanges/CZCE/{raw,quotes,positions,receipts}/<YYYY>/<YYYYMMDD>.*`)。
覆盖 2016-01-04 起的三类日频数据:期货行情、会员持仓排名、仓单日报。每日增量:

```
PYTHONPATH=src python3 -m cta.data.exchanges.czce ingest --date 2026-09-16          # 单日三类
PYTHONPATH=src python3 -m cta.data.exchanges.czce backfill --start 2016-01-04 --end 2026-09-16 --kinds quotes,positions,receipts
PYTHONPATH=src python3 -m cta.data.exchanges.czce coverage                          # 每类每年天数
PYTHONPATH=src python3 -m cta.data.exchanges.czce reconcile --out mism.csv          # 与米筐导出对账
PYTHONPATH=src python3 -m cta.data.exchanges.czce reparse --kinds receipts          # 解析器修订后从 raw 重建 parquet
```

## 1. URL 模式与反爬应对

| 内容 | URL | 备注 |
|---|---|---|
| 日行情 | `https://www.czce.com.cn/cn/DFSStaticFiles/Future/{YYYY}/{YYYYMMDD}/FutureDataDaily.txt` | 竖线分隔文本 |
| 持仓排名 | `…/{YYYY}/{YYYYMMDD}/FutureDataHolding.txt` | 品种榜 + 合约榜,前 20 名 |
| 仓单日报 | `…/{YYYY}/{YYYYMMDD}/FutureDataWhsheet.txt` | 品种 × 仓库 × (年度/等级/品牌)明细 |
| 结算参数 | `…/{YYYY}/{YYYYMMDD}/FutureDataClearParams.txt` | 已接入为 `params`(保证金/手续费/涨跌停),见 `docs/data_exchange_params.md` |
| 交易参数 | `…/{YYYY}/{YYYYMMDD}/FutureTradeParam.txt` | 2025-08-18 起;当日涨跌停/持仓限额,`params` 的 limit_pct 来源 |
| 年度行情打包 | `…/Future/{YYYY}/ALLFUTURES{YYYY}.zip`(2020–)、`…/Future/{YYYY}/FutureDataHistory.zip`(2015–2019)、`/cn/exchange/datahistory{YYYY}.zip`(2010–2014) | 仅行情;入口页 `/cn/jysj/lshqxz/H077003019index_1.htm` |

反爬(瑞数 JS 挑战):同目录的 `.htm` 与年度 `.zip` 直连一律 `412 Precondition Failed`(返回一段混淆 JS,需要浏览器执行后写 cookie)。
**`.txt` 版本不受挑战保护**,普通 UA 直连即 200,非交易日 404(`.xls` 只在 2016 年前后存在,2026 已 404)。
本次回填直连约 6 300 次 `.txt` 请求(每条流 ≥1 s 间隔;持仓/仓单阶段按日期区间并行跑了 3–4 条流,合计约 0.5 请求/秒)未被限流,0 次重试。
回填流程:`backfill --kinds quotes`(年度包 + 当年逐日)→ 按日期区间并行 `backfill --kinds positions,receipts` → 解析器修订后 `reparse --kinds positions,receipts` 从 raw 重建全部 parquet → 最后跑一次全区间 `backfill` 确认 0 次请求(所有工作日要么已落盘要么在 missing.log)。

回退链:`Fetcher.get()` 直连 → 412 时改走本机 Chrome 的 CDP 代理(`http://localhost:3456`,web-access skill),在郑商所同源标签页内 `fetch()` 并以 base64 带回(自动携带挑战 cookie)→ 其他状态码/网络错误按 5s→10s→…→120s 退避重试 5 次。
年度 zip 全部经这条回退取得(10 个,0.7–3 MB);`.txt` 全部直连。`--cdp-proxy none` 可关闭回退。

## 2. 文件格式与字段映射

编码:2016–2017 文件为 GBK(标题行前有几个乱码字节),2018 起 UTF-8;`decode_text()` 先按 UTF-8 严格解码,失败退回 GB18030。
合约代码为 3 位年月(`CF609`),用 `normalize_contract(code, "CZCE", file_date)` 按文件日期推断十年位 → `CF2609`;年度打包按每行的交易日期推断。

### 行情 → `QUOTE_COLS`

表头(2020 及以前叫"品种月份/空盘量",2021 起叫"合约代码/持仓量",按名称定位):

| 文件列 | 字段 | 处理 |
|---|---|---|
| 合约代码 / 品种月份 | contract, symbol | 规范化;`小计/合计/总计` 行与不匹配 `^[A-Z]{1,2}\d{3,4}$` 的行(期权在另一文件)剔除 |
| 昨结算 / 今结算 | prev_settle / settle | 原值 |
| 今开盘 / 最高价 / 最低价 / 今收盘 | open/high/low/close | 交易所用 0 表示无成交价,统一置 NaN |
| 成交量(手) / 持仓量(空盘量) | volume / open_interest | **交易所原值,不折算口径**(见 §3) |
| 成交额(万元) | turnover | ×10 000 → 元(与仓库 `min_dominant_turnover_cny` 同单位) |
| 涨跌1/涨跌2/增减量/交割结算价 | — | 不入库 |

年度打包每品种一个 txt(2016–2019 为单文件 `FutureDataHistory.txt`),多一列"交易日期",其余相同;在 11 个抽样日上与每日文件逐字段全等(2016-12-30 … 2024-06-03,每日 134–223 个合约),因此 2016–2025 的 quotes parquet 直接由年度包生成,原 zip 保存在 `raw/quotes_annual/`,当年(2026)逐日抓 `.txt`。

### 持仓排名 → `POSITION_COLS`

文件按空行分块,块头 `品种：棉花CF  日期：…`(品种榜)或 `合约：CF609  日期：…`(合约榜);每块 10 列:名次 | 会员 | 成交量 | 增减 | 会员 | 持买仓量 | 增减 | 会员 | 持卖仓量 | 增减,末行 `合计`。
品种榜 `contract` = 品种代码(如 `CF`),合约榜 `contract` = 规范化合约;`合计` 行 `is_total=True, rank=0`,会员名为空。2016 年合计行无千分位,2021 起有,`_num()` 统一去逗号。
三列榜单名额不一定相同(成交量榜可能只有 8 家而持仓榜 20 家),缺位的会员交易所写 `-`、数值留空 → 会员名置空、数值 NaN(2016 年每日约 40 行,不是解析错误)。
2021 年前表头"成交量(手)",之后"交易量(手)";2020 年前会员名不带"(代客)"后缀。`品种：PTA` 映射为 `TA`;2016 年动力煤同时有旧代码 `TC` 与新代码 `ZC`,按文件原样保留。

### 仓单日报 → `RECEIPT_COLS`

块头 `品种：白糖SR 单位：张 日期：…`,列集合因品种而异(年度/等级/产地/品牌/仓库-厂库/升贴水),按表头名定位 `仓单数量`(PTA 有"完税"+"保税"两列,相加)与 `当日增减`。
一行 = 品种 × 仓库:优先取仓库的 `小计` 行;无小计的仓库(2016 年动力煤/硅铁等一仓一行)取其明细之和。`总计` 行 → `warehouse="合计", is_total=True`;个别块没有总计行时按仓库求和补一行(仅 2016 年少数品种出现)。
苹果、红枣、花生另有"预报数量"表(机构编号/预报数量),不是仓单,整块跳过——因此苹果(只有预报)没有仓单行。`warehouse` 用仓库简称;同一品种同名仓库不会重复出现。
强麦(WH)自 2020-06 起交割凭证改为"交割确认书",列名 `确认书数量`,按仓单处理(`_RECEIPT_QTY_HEADERS`);2016–2020-05 的强麦块在 `总计` 之后还跟一张"可交割品牌"附表(同样以 `仓库编号|仓库简称` 开头、无数量列),解析时遇到第二张表头重新识别列,且 `总计` 之后到下一品种前一律忽略。

## 3. 成交量/持仓量口径

- 郑商所 **2019-12-31 及以前为双边计算,2020-01-01 起改为单边**。依据:官网"历史行情下载"页脚注"自2020年1月1日起,成交量、持仓量、成交额、行权量均为单边计算";数据上 CF 全部合约持仓量 2019-12-31 为 1 434 454 → 2020-01-02 为 694 322(约减半),SR/TA/MA 同。
- 模块常量 `SINGLE_SIDED_FROM = 2020-01-01`,`counting_basis(date)` 返回 `double`/`single`。**规范化数据保留交易所原值,不折算**;需要跨期可比时把 2020 年前的 volume/open_interest/turnover 除以 2。
- 米筐导出同样保留交易所原值:对账里"2020 年前除以 2"的匹配率(CF 0.51)显著低于原值匹配率(0.85),说明米筐没有折算。上期所/大商所一直是单边,拼接跨交易所因子时注意 2020 年前的郑商所量能是其他交易所的 2 倍口径。

不一致的类型与原因(合计 9 180 行,占 8.2%;下表行数取自 2016–2025 的分类统计,2026 上半年同分布):

| 类型 | 行数 | 样例 | 原因 |
|---|---|---|---|
| 无成交行 OHLC | (已按约定视为一致) | 2016-01-12 CF1607:交易所 0/0/0/0、米筐 11135×4 = 当日结算价 | 米筐对无成交合约用结算价填 OHLC;本仓库置 NaN(`validate` 约定) |

| open_interest | 365 | 2017-07-14 CF1707:交易所 0、米筐 1 440 | 交割月最后交易日后交易所持仓清零/配对,米筐保留盘中值 |

## 6. 已知坑

- `.htm` 版本 412,不要再试各种 Referer/cookie 组合;`.txt` 才是可直连的版本,内容与 `.htm` 表格一致(浏览器里 `.htm` 的 innerText 与 `.txt` 逐字段核对过 2026-09-11)。
- 年度 zip 直连 412,但 2025 的 zip 在浏览器同源 `fetch` 下 200(1.6 MB);2016 zip 内是单文件 `FutureDataHistory.txt`,2020 起每品种一个 `{SYM}FUTURES{YYYY}.txt`。当年没有 zip。
- 2016–2017 文件是 GBK,`file` 识别为 ISO-8859;不要按 UTF-8 强解。
- 交割月合约偶见"成交量>0 但 OHLC 全 0"(2016 年 11 行),交易所把交割/期转现成交计入成交量;`base.validate` 要求有成交必有正价,解析时把 0 价置 NaN 后通过。
- 2016-01-04 持仓排名里动力煤有 `TC`(旧)与 `ZC`(新)两个品种代码并存;仓单里 2016 年 PTA 块头写 `品种：TA`、2026 写 `品种：PTA`。
- 仓单日报的"有效预报"列不是仓单,苹果只有预报表 → 无仓单行;红枣/花生同时有预报表与仓单表,只取后者。
- 持仓排名品种榜的 `contract` 列存品种代码(与合约榜区分靠是否含数字);按合约筛时先 `contract.str.len() > 2`。
- 交易所文件里的合计行(行情"小计/总计"、持仓"合计"、仓单"小计/总计")在 2016 年无千分位、2021 起有,数值解析统一去逗号。
- `missing.log` 只区分 404(节假日或未发布)与 empty(文件存在但解析为空);周末不探测。补当日数据前先确认交易所已发布(通常 15:30 后)。
- `Fetcher` 的 CDP 回退依赖用户 Chrome 已开启远程调试且 web-access 代理在跑;没有代理时 412 会在退避重试后放弃,对应日期不会写入 missing.log(再次运行会重试)。
