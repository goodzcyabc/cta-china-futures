# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

China commodity-futures CTA: research backtest, daily order generation and paper trading on **one code path**. Champion strategy is v0.3 (time-series momentum + carry + exchange warehouse-receipt factor). Docs, reports and the design log are written in Chinese; dates in them are Beijing time (`TZ=Asia/Shanghai date`). Overview and plain-language method: `README.md`; docs index: `docs/README.md`; roadmap: `TODO.md`; operations runbook: `docs/deployment.md`.

## Environment and commands

Python 3.12 in a project venv. `scripts/setup_env.sh` creates `.venv`, installs the pinned `requirements-dev.txt`, and adds `src/` and `research/` to the venv's import path, so no `PYTHONPATH` is needed. Tool settings: `ruff.toml`, `mypy.ini`, `pytest.ini` (no `pyproject.toml`; the project is not pip-installed). Run everything from the **repo root**: CLI defaults, caches and many real-data test guards use cwd-relative paths (`Path("data/...")`) and silently skip elsewhere.

```bash
scripts/setup_env.sh                                                   # once per checkout/worktree
.venv/bin/python -m cta.cli --help                                     # research | live | report | paper
.venv/bin/python -m cta.cli research --config configs/strategy_v03.yaml   # -> results/<cfg_digest>_<instr_digest>_stitched/
.venv/bin/python -m pytest                                             # tests/ + research/tests/
.venv/bin/python -m pytest --ignore tests/test_paths_agree.py          # skip the slow 29-day replay
.venv/bin/python -m pytest -rs research/tests/test_composite.py        # -rs shows why real-data tests skipped
.venv/bin/ruff format --check src research tests scripts && .venv/bin/ruff check src research tests scripts && .venv/bin/mypy src research/cta_research   # CI gates
```

- CI (`.github/workflows/ci.yml`, Python 3.12) runs the same gates. Only `data/benchmarks/` and `data/sample/` are tracked; other `data/*` and `results/` are gitignored, so real-data tests skip in CI. `tests/test_sample_data.py` runs end to end on the public sample in every environment.
- A fresh worktree has no local data. Symlink `data/ricecta`, `data/exchanges`, `data/external` and `results` from the main checkout one by one (`ln -s <main>/data data` would create `data/data` and every real-data test would skip), then run `scripts/setup_env.sh` in the worktree. Check with `pytest -rs`; a run with skipped real-data tests says nothing about data/signal/execution changes.
- Some real-data tests need gitignored `results/` artifacts: `results/settle_baseline/` (from `research/scripts/settle_baseline.py`) and `results/quarterly_walkforward/equity_B_S3.csv` (from `research/scripts/quarterly_walkforward_diagnostic.py --mode full`; without it `research/tests/test_adaptive_quarterly.py` fails rather than skips).
- With local data the suite is not side-effect free: it rebuilds `data/exchanges/<EX>/quotes_all.parquet` when stale and writes `data/exchanges/SHFE/reconcile_ricequant.json`.
- mypy is strict with `warn_unused_ignores` (a stale `# type: ignore` fails). Only `tests/test_boundaries.py` imports `cta.cli` (import only); no test runs its commands, so smoke-check changes with `--help`.

## Layout: production vs research

- `src/cta/` is production: everything the daily paper job and order generation import. `research/cta_research/` is research code (candidate factors, research signals, evaluators, alt-data pipelines, the frozen legacy engine); `research/scripts/` are per-round research scripts; `research/tests/` their tests.
- Production must not import research. The one exception is `cta.pipeline._extra_factors_of`, which lazily imports `cta_research.factors.composite` when a config puts `msf` in `signals.weights` (only `configs/strategy_v06_msf.yaml`, a demo). `tests/test_boundaries.py` enforces this for `src/cta` and `scripts/*.py` (including string imports) and imports the production entry points with `research/` off the path. Research code may import production code.
- `cta.analysis` (paper acceptance, attribution, leave-one-out, paired statistics) is production-side read-only diagnostics used by `scripts/paper_acceptance.py` and `scripts/portfolio_diagnostics.py`.

## Architecture

**Data** (`src/cta/data/`). `DataSource` protocol in `data/source.py`; `--source` on `research`/`live` (default `stitched`) picks:
- `RicequantParquetSource`: proprietary vendor export in `data/ricecta/data` (never commit it), 2016-01-04 → 2026-06-05. Its per-contract table has no settlement column and it has no receipts, so `--source ricequant` fails in `build_panels` for every shipped config (`data.settle: official` rejects close-as-settle).
- `ExchangeSource`: the exchange-direct store `data/exchanges/<EXCH>/` (SHFE, INE, DCE, CZCE). Append-only: raw downloads under `raw/`, one normalized parquet per day per kind (`quotes|positions|receipts|params`); `Store.write_day` refuses to overwrite. `--exchange-root` points it at another store (e.g. the extracted sample). `dominant_rule`: `max_oi` (default, what paper books use after the cutover) or `oi_1.1x` (approximates the vendor dominant table, 99.73% daily agreement; reproduces the official baseline on the local exchange store, see `docs/research/source_check.md`). Each exchange module has its own CLI (`python -m cta.data.exchanges.<shfe|ine|czce|dce|params> --help`); `scripts/fetch_exchange_data.sh` backfills all four. After a parser fix, re-parse from raw (`czce/dce reparse`, or `backfill … --overwrite` for shfe/ine/params), then delete `quotes_all.{parquet,stamp}` (a cache keyed by day count that a reparse does not invalidate).
- `StitchedSource` (`default_stitched`): vendor rows up to the cutover (2026-06-05), exchange rows after; vendor rows get the exchange's official settle/prev_settle, and a missing settle is never filled from close (`build_panels` raises). Receipts and reg events come only from the exchange store. The vendor dominant table (switch at 1.1× open interest) and the exchange `max_oi` rule differ; backtesting v0.3 throughout with `max_oi` gives monthly Sharpe 0.89 vs 1.06. Do not change the paper books' rule during the acceptance window.
- DCE (whole site) is behind an anti-bot JS challenge and is fetched through a local Chrome DevTools proxy (`localhost:3456`); CZCE `.txt` files are direct, its annual zips need the proxy. Never try to defeat the challenge another way. If the DCE fetch fails in the daily job, every book holding a DCE contract fails at stage `settle` and writes `FAILED.json`; fix the cause and rerun catchup. Exchanges publish intraday files with empty settlement, so today's data is never ingested before 16:30 Beijing.
- Public sample: `data/sample/exchanges_sample.tar.gz` (CU, RB, M, SR; 2021–2024), built by `scripts/make_sample_data.py` (byte-identical for the same output path and package versions), used by `configs/sample.yaml` and `tests/test_sample_data.py`.

**Panels** (`continuous/roll.py`, `pipeline.build_panels`). The held contract switches only after the dominant candidate is the same for 3 days and only forward in maturity. `sched_next` (the contract held on T+1) is shared by the engine and the order generator. `adj_close` is ratio back-adjusted and used only for signals; compare returns, not levels. Sizing, PnL, margin and limits use the real held contract. `configs/instruments.yaml` supplies tick, margin, fees and limit_pct.

**Signals** (`pipeline.compute_signals`, `signals/core.py`). Vol → tsmom → optional `tick_filter` → optional `reg_overlay` (paper book `paper/v01r`) → carry → `receipts_level` (only if it is a key in `signals.weights`) → extra factors → sector/symbol menus → `combine` (or `combine_tv` when `factor_weighting: inverse_vol`) → vol targeting → gross cap → stateful `trade_buffer` (`exposure_buffer`). `combine` is a NaN-aware weighted mean × √(n_active/n_max), clipped to [−1, 1].

**Execution** (`src/cta/execution/`), shared by `backtest/engine.py`, `live/orders.py` and `paper/`:
- `plan.plan_lots`: T close of the T+1 contract → round lots → proportional margin cap → `lot_band`; full closes are never banded.
- `ledger.execute_day`: absolute targets; rolls are two legs that fill together or not at all; legs are pre-checked for missing quote, empty open or limit-lock; fill = open ± slippage ticks; unfilled targets are not carried forward.
- `ledger.mark`: marks to each held contract's official settle (engine non-strict, paper strict).
- "Next open" is the exchange daily-bar open: for night-session products the T+1 fill is the calendar-T 21:00 night open. Point-in-time reasoning about data published after 15:00 must account for this.
- `tests/test_paths_agree.py` asserts engine and day-by-day paper path agree exactly. `execution.fill` in the config schema has no effect but feeds the pinned config digests; leave it.

**Paper trading** (`paper/runner.py`, `scripts/paper_daily.sh`, `deploy/com.cta.paper.plist`; see `docs/deployment.md`):
- Five books, each tied to one config: `paper/v01`→`strategy.yaml` (v0.1, the only book that ingests data; runs first), `paper/v03`→`strategy_v03.yaml` (champion), `paper/v03p`, `paper/v01r`, `paper/v05` → `strategy_v03p/v01r/v05.yaml`. The CLI does not check the pairing; always pass `--book` with its `--config`. `configs/paper_protocol.yaml` keeps old labels with a `dir` field per book.
- `PaperBook` on a directory without `state.json` would create a fresh 3M book, so the CLI refuses a `--book` without `state.json` unless `--init`, and `paper_daily.sh` alarms instead of running. Never point `--book` at `paper/` or `paper/log/`.
- A step stages everything in `<book>/.txn/<date>/` and commits with `os.replace`, writing `state.json` last; on failure it writes `FAILED.json` and leaves state unchanged; rerunning `catchup` is idempotent. A settled day cannot be recomputed; never hand-edit `state.json`. Side-effect-free check: `paper step --date <settled day> --no-ingest --book … --config …` → "already settled".
- `paper_daily.sh` runs with `.venv/bin/python` (if `.venv` is missing it alarms and runs no book; run `scripts/setup_env.sh` in that checkout first), scheduled by launchd after the exchanges publish settlement (see `docs/deployment.md`). It `git add`s the five book dirs, commits **whatever is staged**, and pushes `HEAD`. Keep the checkout that runs it on `main` with nothing staged around run time, do branch work in a worktree, and never merge into it while the job runs.
- Trading days are Mon–Fri minus `configs/holidays.csv`; an unlisted exchange holiday makes the step fail by design, so append each year's announced holidays.

**Research layer** (`research/`):
- `cta_research.evaluation.candidate_eval` is the three-arm evaluator (candidate alone / static production baseline / 50-50 ex-ante risk-budget blend, same engine and costs), checks R0–R14, verdict. `build_context` raises if the rebuilt baseline target does not match production; the reference-equity match is stored in `baseline_matches_reference` without raising (False fails R13 → `Invalid`), so scripts must still stop on False themselves.
- Research scripts write `results/<name>/` (gitignored) and `docs/research/<name>.md`. Smoke switches differ: `altdata/options/fundamental_signal_diagnostic.py` take `--smoke`; `quarterly_walkforward_diagnostic.py` and `adaptive_quarterly_v1.py` take `--mode smoke|full` (default smoke) and smoke writes to the same default outputs as full, so pass scratch paths. Full runs of the newer diagnostics include the out-of-sample window and count as trials. Only `factor_{screen,combo,newdata,reg,global,spotbasis}.py` and `exec_trials.py` gate the holdout behind `--confirm-holdout`.
- Only some generators keep hand-written text on rerun (`<!-- narrative-top/bottom -->` in `altdata/fundamental_signal/options_diagnostic.py` and `adaptive_quarterly_v1.py`; `<!-- human:start/end -->` in `msf_demo.py`). Every other doc-writing script rewrites its whole doc; back up and merge by hand before rerunning.

## Invariants and research discipline

- **Config and instrument digests.** `StrategyConfig.digest()` and `InstrumentTable.digest()` hash `model_dump()`, defaults included. Adding a schema field or changing an unset default changes the digests, and every later paper snapshot stops matching the pins in `configs/paper_protocol.yaml` (acceptance window 2026-09-23 → 2026-12-15, report 2026-12-16). Make no schema/default changes before the report; add features by reusing existing fields (as MSF does with a `signals.weights` key) or outside the config (as `dominant_rule` does on the data source). Unknown YAML keys are silently ignored.
- New features default to off, keyed on config content, so existing configs stay bitwise identical. Recompute the five paper-book config digests and compare them with `paper_protocol.yaml`.
- Do not edit the five paper-book configs or `configs/instruments.yaml` during the acceptance window (`research/scripts/fundamental_signal_diagnostic.py` also hashes the bytes of `strategy_v03.yaml`). Do not change champion/challenger semantics without the user's decision.
- **Pre-registration.** Every new hypothesis gets a `docs/research/<topic>_prereg.md` committed (`PREREG: …`) before any returns are computed. Scripts find the prereg commit with `git log --follow --diff-filter=A`; keep any move of a prereg a pure-rename commit. Results are appended only to the prereg's final "结果(运行后只追加)" section.
- **Trial count and design log.** `docs/design_log.md` records every trial (running count, currently 60) and every post-hoc change. Corrections are appended as new subsections; earlier text, prereg texts and `report/archive/` are not rewritten (`docs/README.md` maps old paths). Do not flip a wrong direction, add windows or variants after seeing results, or call a reused out-of-sample window clean.
- **Point-in-time checks.** Truncation-invariance tests (rebuild with data cut at date T; nothing ≤ T may change) are the real guard; date-only audits miss night-session timing. Include cuts on a Friday before a weekend release and on a pre-holiday month end. New release-based factors must pass `target_rule="on_or_after"` to `cta_research.signals.fundamental_signals.releases_to_daily`; the default `"legacy"` books weekend releases on the previous Friday and only reproduces trials 50/51.
- **Out-of-sample monthly statistics.** `perf_stats` on a slice starting 2022-01-04 drops January 2022 (the first month-end is the base). Start the slice at the previous trading day (2021-12-31) when quoting out-of-sample monthly Sharpe; several numbers in report v0.5 used the old slice (design log 二十七).
